# Handoff — AS-граф CAIDA serial-2 → CSR

## Почему CSR

- Граф разреженный: ~680 тыс. AS-связей превращаются примерно в 1,36 млн направленных дуг.
- CSR (`indptr`, `indices`) компактно хранит соседей и подходит для алгоритмов кратчайших путей SciPy.
- Типы дуг хранятся отдельно в `edge_types.npy`: веса легко менять при изменении штрафа `α`, не перестраивая топологию.
- Не нужна плотная матрица смежности или графовая СУБД.

## Альтернативы хранения графа

| Подход | Плюсы | Минусы | Для нашей задачи |
|---|---|---|---|
| **CSR (SciPy + NumPy)** | Компактное хранение, быстрый обход соседей, алгоритмы кратчайших путей | Неудобно часто изменять рёбра | **Выбран**: статичный большой граф |
| Списки смежности (`dict`/`list`) | Просто создавать и менять связи | Python-объекты расходуют больше памяти; вычисления требуют отдельной реализации | Подходит для прототипа |
| NetworkX | Удобный API, отладка и анализ графов | Большие накладные расходы на память и скорость | Для небольших проверок |
| Плотная матрица смежности | Быстрый доступ к любой паре вершин | Память `O(|V|²)` даже при малом числе связей | Не подходит |
| Графовая СУБД (Neo4j) | Запросы и интерактивная работа со связями | Дополнительная инфраструктура; не ускоряет массовые численные расчёты сама по себе | Избыточна |

**Вывод:** граф CAIDA почти не меняется в ходе экспериментов, зато многократно используются обходы и кратчайшие пути. Поэтому CSR даёт лучший практический баланс компактности, скорости и простоты. Оригинальный TXT сохраняем для воспроизводимости.

## Формат входа

CAIDA `serial-2`, файл `*.as-rel2.txt` или `.gz`:

- `provider|customer|-1|source` → `provider→customer` (`downstream=2`) и `customer→provider` (`upstream=1`);
- `peer|peer|0|source` → две дуги `peer=3`.

Дополнительное поле `source` допустимо, но сейчас не сохраняется. Повторы одинаковых связей удаляются; противоречивые типы связей вызывают ошибку.

## Результаты

- `graph.npz` — CSR-топология, `data=1`, дуги направленные;
- `edge_types.npy` — типы дуг, **в том же порядке, что `graph.indices`**;
- `asn_ids.npy` — `asn_ids[внутренний_индекс] = настоящий ASN`;
- `metadata.json` — статистика, имя и SHA-256 исходного файла.

Вычислительный граф при параметре `α ≥ 0`:

`w(u,v) = 1 + α`, если дуга upstream; в остальных случаях `w(u,v) = 1`.

## Запуск

```bash
python -m pip install -r requirements.txt
python -m src.graph build data/raw/20261101.as-rel2.txt.gz --out data/processed
python -m src.graph inspect --dir data/processed
python -m unittest discover -s tests -v
```

Исходный файл CAIDA пользователь помещает в `data/raw/` самостоятельно. Код не скачивает датасет.

## Следующий этап

Выбрать множества `S` (Source AS), `D` (существующие DNS), `C` (кандидаты). Создать взвешенный CSR с нужным `α`, рассчитать расстояния от источников и затем матрицу улучшений `A[s,c]`. ACO будет работать с этой матрицей, а не запускать поиск путей на каждом шаге.

**Ограничение:** кратчайшие пути по этому графу — упрощение, не симуляция BGP. Типы отношений CAIDA являются оценками. Перед крупным запуском проверьте число конфликтующих связей и связность графа.
